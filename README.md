## 1. Отчет об исследовании

### 1.1. Цель и исследовательский пробел

Цель работы — проверить возможность раннего выявления риска профессионального выгорания педагогов по данным региональной государственной образовательной ГИС СО «ЕЦП» и оценить, дает ли ML-модель сигнал сверх простого бейзлайна.

По обзору литературы существующие работы прогнозируют выгорание в основном на специально собранных опросных данных, на ограниченных административных выборках или на вторичных и синтетических датасетах. Ключевой пробел: ни одна из рассмотренных работ не использует данные региональной государственной образовательной ГИС как источник предикторов. Настоящий проект закрывает этот пробел: ML-сервис встраивается как внешний прогнозный модуль через шину ГИС СО «ЕЦП», не вмешиваясь в ядро системы.

<img width="3037" height="1963" alt="auc_boxplot" src="https://github.com/user-attachments/assets/839d8d26-eb9c-489f-8d4c-b3b7434425c3" />


### 1.2. Данные

Использован синтетический датасет — симулятор выгрузки ГИС СО «ЕЦП». В нем 10 761 строка панели «педагог × неделя», 295 педагогов, 1 597 строк с целевой меткой. Положительный класс `burnout_level >= 2` — 119 строк, доля 7,5 процента.

Целевая переменная `burnout_level` соответствует фазам Бойко:

- 0 — нет признаков;
- 1 — напряжение;
- 2 — резистенция;
- 3 — истощение.

Для бинарной постановки использован риск «средне-высокий»: `burnout_level >= 2`.

В симуляторе заложены S-образная динамика выгорания, AR(1)-шум, сезонность и школьные шоки, усталость от волн опросов, смещение неответа при высоком латентном уровне, найм и увольнения, в том числе зависимость увольнений от уровня выгорания.

**Важно:** метка есть только в недели опросов, поэтому модель предсказывает наблюдаемую метку самоотчета, а не латентное состояние педагога. Корреляции в датасете — следствие генератора, а не доказательство причинности.

### 1.3. Постановка и методология

Решалась задача бинарной классификации: предсказать риск `burnout_level >= 2` для педагога на той же неделе, где доступна метка опроса.

Использованы признаки:

- сырые поведенческие: `event_hours`, `activity_hours`, `act_avg_participants_per_hour`, `act_msg_cnt`, `act_msg_char_cnt`;
- инженерные: rolling-средние за 4 и 12 недель, отклонение от базовой медианы первых 6 недель, дельты, лаги, `chars_per_msg`;
- история таргета: `prev_level`, `past_level_mean`, `past_level_max`, `n_pastSurveys`, `has_prior`;
- сезонные: `week_of_year`, `month`, `tenure`.

Основная модель — RandomForest с медианной имитуацией и `class_weight="balanced_subsample"`. Подбор гиперпараметров: `RandomizedSearchCV`, `GroupKFold(3)`. Финальная валидация: `GroupKFold(5)` по `user_id`, чтобы один педагог не попадал одновременно в train и test.

Лучшие параметры RF:

- `n_estimators=221`;
- `max_depth=12`;
- `max_features=0.5`;
- `min_samples_leaf=25`;
- `min_samples_split=2`.

### 1.4. Основные результаты

Финальная RF-модель на 5-fold `GroupKFold` показала:

- ROC-AUC — 0,8824;
- PR-AUC — 0,6983;
- Brier score — 0,0590.

При пороге 0,5:

- precision — 0,584;
- recall — 0,731;
- F1 — 0,649.

Лучший F1 — 0,717 — достигается при пороге 0,673.

Confusion matrix при пороге 0,5:

- TN = 1416;
- FP = 62;
- FN = 32;
- TP = 87.

PR-AUC 0,698 при доле позитива 7,5 процента — это примерно lift 9,3 раза относительно случайного классификатора.

Сравнение с бейзлайном:

- на сырых признаках baseline ROC-AUC 0,580, RF 0,611, прирост 0,031;
- с инженерией без истории baseline 0,690, RF 0,746, прирост 0,056;
- полная модель с историей таргета дает ROC-AUC 0,882.

Ablation по группам признаков:

- сырые 5 признаков — ROC-AUC 0,611, PR-AUC 0,122;
- поведение 36 признаков — ROC-AUC 0,746, PR-AUC 0,386;
- поведение плюс сезон 39 признаков — ROC-AUC 0,749, PR-AUC 0,372;
- только история таргета 5 признаков — ROC-AUC 0,806, PR-AUC 0,545;
- все 44 признака — ROC-AUC 0,882, PR-AUC 0,698.

Главный вывод: основной прирост дает синергия «поведение плюс история прошлых опросов». История таргета сама по себе дает ROC-AUC 0,806, поведение без истории — 0,746. Для новых педагогов без истории доступна «честная» поведенческая модель с ROC-AUC около 0,75.

Топ признаков по важности:

- `chars_per_msg_rel`;
- `prev_level`;
- `past_level_max`;
- `past_level_mean`;
- `act_msg_char_cnt`;
- `chars_per_msg_d4`;
- `act_msg_cnt`;
- `act_avg_participants_per_hour_lag1`.

### 1.5. Аудит утечек данных

Проведены обязательные проверки.

- `rolling`/`lag` смотрят только назад — OK.
- `target` соответствует `burnout_level >= 2` на той же строке — OK.
- `prev_level` и `past_level` используют только прошлое — OK.
- Shuffle-test: на перемешанном таргете средний ROC-AUC около 0,51, то есть модель не находит ложных закономерностей — OK.
- Ablation показал, что история дает 0,806, поведение — 0,746, все — 0,882.
- Разброс по фолдам: ROC-AUC 0,892 плюс-минус 0,040, PR-AUC 0,715 плюс-минус 0,056.

Обнаружена мягкая утечка в `_rel` для педагогов с `tenure < 6`: знаменатель использует медиану первых 6 недель, включая будущие значения. Дополнительная проверка `_rel_strict`, где знаменатель — только прошлая expanding-медиана, дала ROC-AUC 0,875 и PR-AUC 0,694 против 0,882 и 0,698 у старого `_rel`. Цена строгой версии небольшая, поэтому для продакшена рекомендуется `_rel_strict`.

Для `tenure < 6` качество модели резко падает, ROC-AUC около 0,34. Это означает, что на первых 6 неделях педагога модель лучше не применять или выдавать только осторожный поведенческий сигнал.

### 1.6. Ограничения

- Данные синтетические; реальная валидация возможна только на данных ЕЦП.
- `burnout_level` — самоотчет, а не объективная истина.
- Есть шум, MNAR-неответы и усталость от волн опросов.
- Положительный класс малочислен: 119 позитивов, поэтому разброс метрик по фолдам заметен.
- Метка доступна только в недели опросов; модель не валидирована на всех неделях.
- Нельзя делать причинные выводы вида «вечерняя активность вызывает выгорание».
- Требуются отдельные проверки справедливости, приватности и организационных рисков.

### 1.7. Выводы и рекомендации

- RF-модель превосходит baseline на всех сопоставимых наборах признаков: прирост 0,03–0,06 ROC-AUC.
- Полная модель достигает ROC-AUC 0,882 и PR-AUC 0,698, что является сильным результатом для синтетического пилота.
- Основной сигнал — поведение плюс история прошлых опросов; только поведение дает около 0,75 ROC-AUC.
- Критических утечек не найдено, но `_rel` лучше заменить на `_rel_strict`.
- Для `tenure < 6` прогнозы ненадежны — их не стоит использовать для кадровых решений.
- Признаки `week_of_year`, `month`, `tenure` в финальной модели практически не дают прироста — их можно убрать.
- Следующий шаг — пилот на реальных данных ЕЦП с комбинированным ground truth: опросы, коллегиальная оценка и интервью с уволившимися.

## 2. КРАТКАЯ ХАРАКТЕРИСТИКА ML-СЕРВИСА

**Название:** Система раннего выявления риска профессионального выгорания педагогов в Свердловской области на данных ГИС СО «ЕЦП».

<img width="3186" height="1984" alt="ml_lifecycle_phased" src="https://github.com/user-attachments/assets/0a58646f-b804-4a56-8cdb-b9b464bfd739" />

**Тип:** внешний прогнозный ML-сервис с REST API, интегрируемый через шину ESB. В ядро ЕЦП не вмешивается.

<img width="3186" height="1986" alt="integration_scheme" src="https://github.com/user-attachments/assets/0648652e-301a-4a28-8a33-ce1cf399d691" />

**Назначение:** выдавать для каждого действующего педагога бинарный риск средне-высокого выгорания `burnout_level >= 2` и вероятность риска для приоритизации профилактических мероприятий.

**Пользователи:** HR-службы, методисты, школьные психологи, региональные органы управления образованием. Сервис — система поддержки решений, а не диагностический инструмент.

**Входные данные:**

- кадровый учет;
- расписание и мероприятия;
- электронный журнал;
- цифровые портфолио;
- лог активности;
- опросы педагогов;
- данные об отсутствиях;
- агрегаты на уровне «педагог × неделя».

**Выходные данные:**

- вероятность риска;
- бинарный класс риска;
- топ-факторы риска;
- дата расчета;
- версия модели;
- запись в `analytics.burnout_risk`.

**Модель:** RandomForest, 44 признака в полной версии, медианная импутация, `class_weight="balanced_subsample"`. Для продакшена рекомендуется `_rel_strict` и отказ от прогнозов при `tenure < 6`.

**Качество на синтетическом пилоте:**

- ROC-AUC — 0,882;
- PR-AUC — 0,698;
- Brier — 0,059;
- recall — 0,731;
- precision — 0,584 при пороге 0,5;
- максимальный F1 — 0,717 при пороге 0,673.

**Интеграция:** подсистемы ЕЦП передают данные через ESB в РБД; ML-сервис состоит из Feature Store, модели и REST API; результаты записываются в хранилище результатов и выводятся в BI-дашборд.

**Жизненный цикл:**

- пилот на синтетических данных;
- переход на реальные данные ЕЦП и опросы;
- первые 6 месяцев — ежемесячные опросы;
- интервью с уволившимися;
- дообучение после каждых 200 увольнений;
- мониторинг drift, калибровки, fairness и качества.

<img width="960" height="540" alt="burnout 005" src="https://github.com/user-attachments/assets/e89515a7-380f-4b64-8f85-28fc1d0ba838" />


**Ключевые ограничения:** синтетическая валидация, самоотчетная метка, мало положительных примеров, риск дрейфа, необходимость защиты персональных данных и запрет на использование сервиса как единственного основания для кадровых решений.
